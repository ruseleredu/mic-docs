Checklist — Projeto final​

  • Proposta do projeto aprovada pelo professor, com o contrato MQTT e o roteiro de testes da bancada (T0)
  • Pelo menos um dispositivo de entrada e um de saída, usados de verdade pela aplicação (T1)

  • MQTT nos dois sentidos com o Node-RED, com LWT, seguindo o contrato (T3)
  • SQLite no Node-RED com CHECK, INSERT preparado e consultas que respondem perguntas do projeto (T4)
  • Simulação completa no Wokwi e um teste automático com o wokwi-cli no CI (T5)
  • Protótipo em bancada com o mesmo firmware, passando no roteiro de testes (T6)
  • Dashboard de operação no Node-RED (T7)
  • Documentação no GitHub: README, contrato MQTT, pinagem, badge do CI e release (T8)
  • Vídeo de apresentação de 3 a 5 minutos, com o link no README e no Moodle (T9)
  • Nenhum token ou senha no repositório; nenhum push --force; cada tarefa num commit Tn:
  • Logout do Git e do gh no computador do laboratório

O Git é a ferramenta de gerenciamento de código-fonte mais utilizada por desenvolvedores profissionais.

  • O Git é um sistema de controle de versão distribuído gratuito e de código aberto, projetado para lidar com tudo, desde projetos pequenos até muito grandes, com rapidez e eficiência.

    winget install --id Git.Git -e --source winget

    git config --list --show-origin

O GitHub CLI traz o GitHub para o seu terminal.

  • O GitHub CLI é uma ferramenta de linha de comando que permite interagir com o GitHub diretamente pelo terminal. Está disponível para Windows, macOS e Linux.

    winget install --id GitHub.cli -e --source winget

  • Status de login do GitHub CLI:

    gh auth status

    winget install Python.Python.3.14

    py --version && python --version && pip --version

    py -m pip install bcrypt

Visual Studio Code: IDE e Editor de Código para Desenvolvimento de Software.

  • O VS Code é um editor de código-fonte gratuito criado pela Microsoft para Windows, Linux e macOS. Inclui suporte para depuração, controle Git integrado, realce de sintaxe, conclusão inteligente de código, snippets e refatoração de código.

    winget install --id Microsoft.VisualStudioCode -e --source winget

    code --list-extensions --profile "ESP32IO"

    {
        "terminal.integrated.defaultProfile.windows": "Command Prompt"

    code --install-extension platformio.platformio-ide --profile "ESP32IO"

    wokwi-cli -h

  • Obtenha seu token em https://wokwi.com/dashboard/ci:

    setx WOKWI_CLI_TOKEN "wok_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"

WinLibs (GCC + MinGW-w64): Compilador C/C++ nativo para Windows, usado pelo PlatformIO no ambiente native.

  • O pio test -e native compila os testes com o gcc/g++ do computador, e o PlatformIO não instala esse compilador. Sem ele, aparece o erro 'gcc' não é reconhecido como um comando interno.

  • WinLibs: baixe a versão mais recente (x86_64, POSIX, UCRT) via GitHub. É portátil e não precisa de administrador.

    powershell -NoProfile -Command "$a = (Invoke-RestMethod https://api.github.com/repos/brechtsanders/winlibs_mingw/releases/latest).assets | Where-Object { $_.name -like 'winlibs-x86_64-posix-seh-gcc-*-mingw-w64ucrt-*.zip' -and $_.name -notlike '*llvm*' } | Select-Object -First 1; curl.exe -L -o (Join-Path $env:TEMP 'winlibs.zip') $a.browser_download_url"

  • Descompacte em %USERPROFILE%\mingw64 e apague o .zip:

    tar -xf "%TEMP%\winlibs.zip" -C "%USERPROFILE%" && del "%TEMP%\winlibs.zip"

  • Acrescente %USERPROFILE%\mingw64\bin ao PATH do usuário (rode uma vez só):

    powershell -NoProfile -Command "[Environment]::SetEnvironmentVariable('Path', [Environment]::GetEnvironmentVariable('Path','User') + ';' + $env:USERPROFILE + '\mingw64\bin', 'User')"

  • Feche e abra o VS Code de novo para ele ler o novo PATH. Depois confira:

    gcc --version

A regra de ouro do projeto

A decisão mora no ESP32. Com o broker ou o Node-RED fora do ar, o dispositivo continua fazendo o seu trabalho e se protegendo. O Node-RED registra, mostra e repassa comandos, que o ESP32 valida e confirma.

Objetivos​

  • Propor um produto IoT pequeno, com escopo que caiba em quatro semanas.
  • Integrar num só firmware os periféricos do semestre: entradas, saídas, periféricos dedicados e interrupção.
  • Definir e documentar um contrato MQTT e respeitá-lo dos dois lados.
  • Guardar, consultar e manter os dados num SQLite pelo Node-RED, e mostrá-los num dashboard.
  • Levar o mesmo firmware do simulador para a bancada, trocando só a configuração de rede.
  • Comunicar o projeto: README, release e um vídeo curto.

for /f "delims=" %i in ('docker compose ls -q') do docker compose -p %i down

static void botao_iniciar(void) {
    gpio_config_t cfg = {
        .pin_bit_mask = 1ULL << BOTAO_PIN,
        .mode = GPIO_MODE_INPUT,
        .pull_up_en = GPIO_PULLUP_ENABLE,

Parte 4 — SQL via Node-RED (SQLite)​

O banco /data/sqlite/projeto.sqlite segue o Lab 08: modo Batch para o esquema, Prepared Statement para tudo o que vem de fora, catch nos erros.

Requisitos:

  1. ≥ 2 tabelas do seu domínio, com NOT NULL e CHECK nas faixas e nos valores válidos, e recebido_em preenchido pelo banco. Uma delas guarda dados periódicos e a outra eventos.
  2. A tabela status abaixo, igual para todos os grupos.
  3. ≥ 3 consultas que respondem perguntas do projeto (as da proposta), e pelo menos uma usa GROUP BY e uma usa LAG() ou LEAD().
  4. Manutenção: índice em recebido_em e retenção do detalhe numa transação (Lab 08, T6).
Tabela comum a todos os grupos
CREATE TABLE IF NOT EXISTS status (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    recebido_em TEXT NOT NULL DEFAULT (strftime('%Y-%m-%d %H:%M:%f', 'now', 'localtime')),
    valor       TEXT NOT NULL CHECK (valor IN ('online', 'offline'))
);
Disponibilidade do nó (LEAD)
SELECT ROUND(100.0 * SUM(CASE WHEN valor = 'online' THEN dt_s ELSE 0 END) / SUM(dt_s), 1) AS disponibilidade_pct
FROM (SELECT valor, (julianday(LEAD(recebido_em, 1, strftime('%Y-%m-%d %H:%M:%f', 'now', 'localtime'))
             OVER (ORDER BY id)) - julianday(recebido_em)) * 86400 AS dt_s FROM status);
Perguntas que valem uma consulta

"Quanto tempo ficou em cada estado?" (LEAD, Lab 08) · "Alguma leitura se perdeu?" (LAG no seq) · "Quantos eventos por hora?" (GROUP BY substr(recebido_em, 1, 13)) · "Quanto tempo entre o alarme e o reconhecimento?" (LEAD na tabela de eventos). Uma consulta que só lista as últimas linhas não conta como uma das três.

Exemplo de referência: câmara climática​

Como a câmara climática dos Labs 05–09 cumpre cada critério (clique para abrir)

A câmara é o projeto que o semestre foi construindo. Serve de exemplo do tamanho esperado e de como os critérios se encaixam. O grupo pode seguir este exemplo, mas precisa acrescentar o que falta nele (planta, alarme com botão e buzzer).

O problema que falta resolver: no Wokwi o LED "aquecedor" não esquenta o DHT22. A solução é uma planta térmica simulada no firmware: o DHT22 mede a temperatura ambiente, e um modelo de 1ª ordem, integrado a cada 1 s por um esp_timer, calcula a temperatura interna:

Modelo da câmara (Euler, Δt = 1 s)
T[k+1] = T[k] + Δt/C · ( P·aq/100 − (G0 + Gv·ve/100) · (T[k] − T_amb) )
C = 120 J/°C · P = 25 W · G0 = 0,5 W/°C · Gv = 2 W/°C   →   constante de tempo C/G0 = 240 s
CritérioNa câmara climática
T1DHT22, potenciômetro (setpoint) e botão; OLED, LEDs aquecedor/ventilador e buzzer
T2ADC1, LEDC em três timers (5 Hz, 25 kHz, 2 kHz), esp_timer e ISR do botão de reconhecimento
T3.../dht, .../pwm, .../alarme (retido), .../status (LWT); cmd/modo, cmd/ack…
T4leituras, atuacao, alarmes, status; energia por modo, trocas do aquecedor, erro × SP
T5cenário que gira o pot e espera AQUECENDO e depois ESTAVEL
T6o mesmo firmware na bancada; a planta continua simulada, o DHT22 lê o ar do laboratório
T7OLED pixel a pixel, modos, histórico T × SP, indicadores

Modos: pot, remoto, auto (ON/OFF com histerese de ±0,5 °C) e pi (Kp = 25 %/°C, Ki = 0,25 %/(°C·s), com anti-windup). Alarme SOBRETEMP acima de SP + 8 °C: aquecedor a 0 %, buzzer, e só se apaga com o botão (ou cmd/ack) e a temperatura de volta.

Com o mesmo modelo, 10 minutos com SP = 37,5 °C dão, como ordem de grandeza:

ModoChega a SP − 0,5 °CTrocas do aquecedorErro RMSEnergia
auto~68 s~39~0,3 °C~1,45 Wh
pi~98 s0 (~26 % contínuo)~0,01 °C~1,45 Wh

A energia é praticamente a mesma; o que muda é o desgaste do atuador e a qualidade da regulação. É o tipo de conclusão que o banco deve sustentar com números.
