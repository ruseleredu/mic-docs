WinLibs (GCC + MinGW-w64): Compilador C/C++ nativo para Windows, usado pelo PlatformIO no ambiente native.

  • O pio test -e native compila os testes com o gcc/g++ do computador, e o PlatformIO não instala esse compilador. Sem ele, aparece o erro 'gcc' não é reconhecido como um comando interno.

  • WinLibs: baixe a versão mais recente (x86_64, POSIX, UCRT) via GitHub. É portátil e não precisa de administrador.

    powershell -NoProfile -Command "$a = (Invoke-RestMethod https://api.github.com/repos/brechtsanders/winlibs_mingw/releases/latest).assets | Where-Object { $_.name -like 'winlibs-x86_64-posix-seh-gcc-*-mingw-w64ucrt-*.zip' -and $_.name -notlike '*llvm*' } | Select-Object -First 1; curl.exe -L -o (Join-Path $env:TEMP 'winlibs.zip') $a.browser_download_url"

  • Descompacte em %USERPROFILE%\mingw64 e apague o .zip:

    tar -xf "%TEMP%\winlibs.zip" -C "%USERPROFILE%" && del "%TEMP%\winlibs.zip"

  • Acrescente %USERPROFILE%\mingw64\bin ao PATH do usuário (rode uma vez só):

    powershell -NoProfile -Command "[Environment]::SetEnvironmentVariable('Path', [Environment]::GetEnvironmentVariable('Path','User') + ';' + $env:USERPROFILE + '\mingw64\bin', 'User')"

  • Feche e abra o VS Code de novo para ele ler o novo PATH. Depois confira:

    gcc --version

Nesta alternativa o produto é uma fonte chaveada de bancada supervisionada: o buck de 18 V dos guias, regulado pelo TL494 (ou pelo SG3525A), com o ESP32 fazendo o que o CI não faz sozinho. O ESP32 gera a referência, limita a razão cíclica, detecta falhas, desliga com segurança e põe a fonte na rede: telemetria por MQTT, histórico no SQLite e comando pelo dashboard.

O projeto junta duas trilhas da disciplina. O hardware e o firmware de controle vêm dos guias de eletrônica de potência; o MQTT, o banco, o dashboard, o Wokwi e o CI vêm dos Labs 01–10.

ESP32 e SG3525A trabalhando juntosa mesma coisa para quem escolher o SG3525A

Comparação TL494 × SG3525Aa escolha do CI, justificada na proposta
Segurança
  • Só 18 V. O projeto usa a fonte de bancada de 18 V limitada em corrente (1 A). Ligar o conversor ao retificador da rede está fora deste projeto.
  • Nenhum pino do ESP32 recebe mais que 3,3 V. O REF do TL494 (5 V), o pino 3, o nó X e o pino 9 do SG3525A só chegam ao ESP32 por divisor ou transistor, como nos guias.
  • O desligamento seguro (amplificador de erro 2 no TL494, pino 10 no SG3525A) é montado e testado antes do primeiro +18 V: com o ESP32 desligado, não pode haver pulsos.
  • Resistores de carga de 10 W esquentam. Não encoste neles com a fonte ligada.

Objetivos​

  • Integrar o ESP32 a um controlador PWM analógico, dividindo o trabalho: o CI regula, o ESP32 supervisiona.
  • Garantir que a rede (Wi-Fi e MQTT) nunca atrasa a supervisão: tempo real e IoT no mesmo chip.
  • Medir a qualidade da regulação com números tirados do banco, e comparar com o que os guias preveem.
  • Testar o firmware no Wokwi com o CI simulado antes de energizar a placa.

for /f "delims=" %i in ('docker compose ls -q') do docker compose -p %i down

2.1 A supervisão não espera pela rede​

O firmware dos guias roda a supervisão no loop(). Com Wi-Fi e MQTT, isso não serve mais: a reconexão do Lab 05 bloqueia o loop() por segundos, e a falha "sem resposta" precisa ser vista em 50 ms. A supervisão vai para uma task própria, de prioridade maior, acordada a cada 2 ms. A rede só lê o que ela publica numa fila.

src/main.cpp (estrutura)
QueueHandle_t filaMedidas;               // supervisão -> rede (último valor, tamanho 1)
QueueHandle_t filaComandos;              // rede -> supervisão (ref, dmax, liga)

void taskSupervisao(void *) {
  TickType_t proximo = xTaskGetTickCount();
  for (;;) {
    vTaskDelayUntil(&proximo, pdMS_TO_TICKS(2));
    aplicarComandos();                   // lê filaComandos sem esperar (timeout 0)
    controlar();                         // o controlar() do guia, sem nenhum Serial nem rede
    if (++n % 50 == 0) xQueueOverwrite(filaMedidas, &medidas);   // 10 Hz para a rede
  }
}

void setup() {
  // ... desligamento seguro primeiro, como no guia
  filaMedidas = xQueueCreate(1, sizeof(Medidas));
  filaComandos = xQueueCreate(8, sizeof(Comando));
  xTaskCreatePinnedToCore(taskSupervisao, "sup", 4096, NULL, 5, NULL, 1);
  // Wi-Fi, MQTT e OLED ficam no loop(), prioridade 1
}

Quem migrou para o ESP-IDF no Lab 09 faz igual: a task app vira a task da rede, e a supervisão é uma segunda task, de prioridade maior, acordada por um esp_timer ou por vTaskDelayUntil.

2.2 Medindo a razão cíclica por interrupção​

O D~ dos guias é estimado pela tensão do pino 3. Para conferir, o ESP32 mede o pulso de verdade no nó X, por um divisor de 47 kΩ / 10 kΩ (16 V viram 2,8 V) até o GPIO18. Uma interrupção por borda a 21 kHz pesaria na CPU, então a medida é feita em janelas: a cada 200 ms a ISR é ligada, registra 16 períodos e se desliga.

src/supervisao.cpp (trechos)
#define NOX_PIN 18
volatile int64_t tSubida = 0, somaAlto = 0, somaPeriodo = 0;
volatile int bordas = 0;

void IRAM_ATTR isrNoX() {
  int64_t t = esp_timer_get_time();
  if (digitalRead(NOX_PIN)) {
    if (tSubida) somaPeriodo += t - tSubida;
    tSubida = t;
  } else if (tSubida) {
    somaAlto += t - tSubida;
  }
  if (++bordas >= 33) detachInterrupt(NOX_PIN);   // 16 períodos e para
}

// a cada 200 ms, na task de rede:
//   D = somaAlto / somaPeriodo  ·  f = 16e6 / somaPeriodo   (zere as somas e religue a ISR)

A resolução é de 1 µs num período de 47 µs, cerca de 2 %. Compare com o D~ estimado e com o osciloscópio: as três medidas vão para a tabela da T6.

CREATE TABLE IF NOT EXISTS medidas (

    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    recebido_em TEXT NOT NULL DEFAULT (strftime('%Y-%m-%d %H:%M:%f', 'now', 'localtime')),
    estado      TEXT NOT NULL CHECK (estado IN ('DESLIGADO', 'PARTIDA', 'OPERANDO', 'FALHA')),
    motivo      TEXT
);

    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    recebido_em TEXT NOT NULL DEFAULT (strftime('%Y-%m-%d %H:%M:%f', 'now', 'localtime')),
    valor       TEXT NOT NULL CHECK (valor IN ('online', 'offline'))

Indicadores, cada um num inject (o estado de medidas copia o último .../estado, gravado pela function):

Regulação de linha: erro por faixa de Vin (GROUP BY)
SELECT ROUND(vin) AS vin_v, COUNT(*) AS n,
       ROUND(AVG(vo - ref), 3) AS erro_medio_v, ROUND(MAX(ABS(vo - ref)), 3) AS erro_max_v
FROM medidas WHERE estado = 'OPERANDO' AND ref > 0
GROUP BY vin_v ORDER BY vin_v;
Tempo em cada estado (LEAD)
SELECT estado, COUNT(*) AS vezes, ROUND(SUM(dt_s), 1) AS segundos
FROM (SELECT estado, (julianday(LEAD(recebido_em, 1, strftime('%Y-%m-%d %H:%M:%f', 'now', 'localtime'))
             OVER (ORDER BY id)) - julianday(recebido_em)) * 86400 AS dt_s FROM eventos)
GROUP BY estado ORDER BY segundos DESC;
Falhas e tempo até o rearme (LEAD)
SELECT recebido_em AS falha, motivo,
       ROUND((julianday(proximo) - julianday(recebido_em)) * 86400, 1) AS s_ate_rearme
FROM (SELECT *, LEAD(recebido_em) OVER (ORDER BY id) AS proximo FROM eventos)
WHERE estado = 'FALHA';
Quanto se perde no caminho: Vo / (D × Vin)
SELECT ROUND(ref) AS ref_v, COUNT(*) AS n,
       ROUND(AVG(vo / (d_med / 100.0 * vin)), 3) AS vo_sobre_d_vin,
       ROUND(AVG(d_med - d_est), 2) AS d_med_menos_d_est
FROM medidas WHERE estado = 'OPERANDO' AND d_med > 10
GROUP BY ref_v;

Confira na semana 1: o DAC do ESP32 aciona o chip?

O guia do chip não verificou se o DAC do ESP32 chega ao pino analógico de um chip personalizado. Teste primeiro: dacWrite(26, ...) em degraus e o D medido no GPIO18. Se o DAC não chegar, troque o fio do DTC por um terceiro potenciômetro e deixe a malha do Wokwi em malha aberta (o ESP32 mede D, calcula Vo pelo modelo e supervisiona). Registre o que aconteceu no README: é uma descoberta, não um defeito do grupo.

Parte 6 — Protótipo em bancada​

O protótipo é a fonte regulando de verdade, no modo 1, com a supervisão e a rede funcionando ao mesmo tempo. A montagem e a calibração seguem o guia de cooperação do CI escolhido; o firmware é o da Parte 2 com -DALVO_BANCADA, gravado com pio run -e bancada -t upload. A rede é a do laboratório e o broker é o Mosquitto local.

6.1 Ordem de montagem​

  1. Desligamento seguro e DTC (ou grampo, no SG3525A) primeiro. Teste sem o ESP32: +18 V ligado, nó X sem pulsos.
  2. LM324 (ou LM358) e os divisores. Confira cada tensão com o multímetro antes de ligar ao ESP32.
  3. ESP32, OLED, botão e LED. Firmware gravado, ainda sem o +18 V: o serial mostra DESLIGADO SUBTENSAO.
  4. Calibração do guia, registrada em docs/calibracao.md (as constantes CAL_*, V_RAMPA, V_DTC_OFS ou a VEB do grampo, com os valores medidos).
  5. Rede tipo 3 e o modo 1.

Cronograma sugerido​

A bancada é mais longa aqui

Uma fonte chaveada leva mais tempo para montar e calibrar que um tema de sensores. Comece o estágio de potência na semana 2, em paralelo com o firmware, e use a montagem da experiência se ela já existir.

Preveja antes de rodar​

  • P1: por que a supervisão precisa de uma task própria e a telemetria não? Calcule quanto tempo a reconexão Wi-Fi do Lab 05 pode bloquear o loop() e compare com os 50 ms da falha "sem resposta".
  • P2: no modo 1, se o ESP32 travar com o GPIO27 em nível alto, o que continua protegendo a fonte? E se ele travar em nível baixo?
  • P3: por que o rearme não existe pelo MQTT? Dê um cenário em que um rearme remoto causaria dano.
  • P4: a consulta Vo / (D × Vin) deu um valor abaixo de 1. De onde vem a diferença? Ela muda com a carga?
  • P5: o que o Wokwi não conseguiu mostrar e só apareceu na bancada? Cite um exemplo medido.

Logout do seu ambiente dev, git e gh​

Ao terminar — máquina de laboratório

Antes de sair, faça logout para não deixar sua conta do GitHub ativa nesta máquina. Rode os comandos abaixo no Prompt de Comando (cmd), não no PowerShell.

1. Apague a credencial do GitHub salva pelo git, encerre a sessão do gh e remova seu nome e e-mail da configuração global:

(echo protocol=https&echo host=github.com) | git credential reject
gh auth logout --hostname github.com
git config --global --unset user.name
git config --global --unset user.email

Para conferir, este comando não deve mostrar nada:

cmdkey /list | findstr /i github

2. Pare os containers do lab:

for /f "delims=" %i in ('docker compose ls -q') do docker compose -p %i down

3. No navegador, saia da sua conta em github.com e feche todas as janelas.
